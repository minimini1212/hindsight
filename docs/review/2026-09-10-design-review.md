## 🔴 전제를 무너뜨린 것 넷

### 1. 생성된 테스트가 **무엇을 검사하는지**가 문서에 없었다

테스트는 **입력**과 **오라클**(맞았다/틀렸다의 판정 기준)로 이루어진다. 처음 설계는 입력을
재생하는 방법만 자세히 적고 **오라클을 한 줄도 안 적었다.** 그리고 파고들면 이렇게 된다.

- 예외 방아쇠에서 끌어낼 수 있는 유일한 오라클은 「안 던진다」인데,
  `catch (Exception e) { return null; }` 로 통과된다. **존재하는 오라클 중 가장 약하다**
- 지연 방아쇠에는 오라클이 아예 없다. 재생에서는 DB가 가짜라 **180ms가 0ms가 된다**

🔴 그리고 v0의 대표 버그인 **N+1은 예외를 안 던진다.** 지연으로만 잡히는데 지연은 잴 수 없다.
**즉 v0의 데모 버그가 v1의 테스트를 만들 수 없었다.**

**고친 것**: 설계에 「오라클」 절(§6-1)을 새로 만들고 방아쇠별로 정했다.
🎯 **N+1은 시간이 아니라 「SQL 실행 횟수」로 잡는다** — 완전히 결정론적이고 정확히 그 버그를 겨눈다.
그리고 이게 **특성화 테스트**(원래 이랬다를 굳히는 것)이지 명세 테스트가 아니라고 명시했다.

### 2. 채점기가 **옳은 패치를 벌주고 있었다**

가짜 DB는 **기록된 질의에만** 답할 수 있다. 그런데 제대로 된 수정은 대개 질의를 바꾼다 —
N+1을 조인으로 합치기, `WHERE` 절 추가, 캐시 넣기, 배치로 묶기.

> 🔴 **경계를 그대로 두는 패치는 통과하고, 경계를 바꾸는 패치는 실패한다.**
> **얕은 패치가 구조적 수정보다 높은 점수를 받는다.** 정확히 거꾸로다.

이건 자동 프로그램 수정 분야에서 20년간 측정된 **과적합**이고, 실측 과적합률이 연구에 따라
73~98%다. 그 분야가 「테스트 통과」를 정답 신호로 쓰기를 포기한 이유다.

**고친 것**:
- 세 번째 결과 **`DIVERGED`** 를 만들었다 — 실패도 통과도 아니고, **「무엇이 무엇으로 바뀌었나」를
  붙여 사람에게 넘긴다.** 오히려 가장 좋은 PR 설명이 된다
- 채점을 **네 겹**으로 쌓았다 (설계 §7-2): ㉠ 패치 전에 정말 실패했나 ㉡ 패치 후 통과하나
  ㉢ **앱의 기존 테스트가 다 통과하나** ㉣ 되돌리면 다시 실패하나
- 🔴 ㉢을 **고리 안으로 옮겼다.** 처음엔 PR 이후 CI에 맡겼는데, 그러면 프로젝트의 진짜 테스트를
  한 번도 안 돌린 패치로 PR을 자동 생성하게 된다
- 주장 자체를 줄였다: *"채점기는 명백히 틀린 패치를 걸러낸다. 맞는 패치임을 증명하지는 않는다."*

### 3. 만드는 순서가 **핵심을 맨 뒤에** 두고 있었다

가장 위험하고 오래 걸리는 바이트코드 작업이 v0이었고, 「이 프로젝트의 존재 이유」라고 스스로
적은 고리가 v2였다. **일정이 밀리면 잘려나가는 건 항상 뒤쪽이다.**

그리고 일정 자체가 낙관적이었다. v0 2~3주는 실제로 5~7주이고, 범인은 **JDBC 계측**이다 —
인터페이스 셋에 걸친 90개 남짓의 메서드, 파라미터 곁표, 배치 처리, 그리고 커넥션 풀 프록시와
드라이버 구현체가 **둘 다 잡혀 질의가 두 번 기록되는** 문제.

**고친 것**: 순서를 뒤집었다.

| | 처음 | 🔄 바꾼 뒤 |
| --- | --- | --- |
| v0 | 에이전트(바이트코드·셰이딩·클래스로더) | **고리 전체.** 기록은 `Filter` + `DataSource` 감싸기 — 200줄, 오늘 된다 |
| v1 | 고리 | **기록기를 진짜 에이전트로 갈아끼운다.** 이미 도는 시스템이 회귀 검사가 된다 |

🎯 **2~3주 뒤에 데모 영상이 나온다.** 기록기를 두 번 만드는 값은 나흘쯤이고,
얻는 것은 **「위험보다 데모가 먼저 온다」** 는 것이다.

### 4. 60초 × 64MB가 **산수가 10배 안 맞았다**

초당 200요청 × 60초 = 12,000건, 요청당 7KB만 잡아도 84MB다. **실제로 담기는 건 3~8초치다.**
그런데 파일에는 「최근 60초」라고 적힌다. 🔴 **이 프로젝트가 막으려는 「모름을 없음으로 접기」를
도구가 자기 자신에게 저지르고 있었다** — 읽는 사람은 30초 전에 시작된 커넥션 누수가
**일어나지 않았다고** 결론 낸다.

**고친 것**: 저장을 두 층으로 나눴다 (데이터 계약 §2-1).

| 층 | 크기 | 담는 것 | 쓰는 곳 |
| --- | --- | --- | --- |
| 전문 | 16MB · 5초 | 본문·파라미터·결과 행 | **재생** |
| 요약 | 16MB · 60초 | SQL 지문과 횟수, 요청 줄 | 사람이 원인을 찾는 데 |

그리고 **담으려던 시간과 실제 담긴 시간을 둘 다 파일에 적는다.**

## 🔴 채점표를 우회하는 구멍들

처음 화이트리스트는 `src/main/**` 였다. 여기로 다 빠져나간다.

| 구멍 | 어떻게 통과시키나 | 고친 것 |
| --- | --- | --- |
| `.github/**` | **CI를 고쳐서** 통과시킨다. 설계가 「기존 CI가 회귀를 본다」고 맡겨 놓은 바로 그 CI다 | 금지 |
| `gradle/**`·`*.gradle*` | 빌드를 고친다 | 금지 |
| `src/main/resources/**` | `application.yml` 한 줄로 검증을 끄거나 기능 플래그를 뒤집는다 | 자동 통과 대상에서 뺐다. 중간 확신도로 내린다 |
| Hindsight 자신의 모듈 | 자기 채점기를 약하게 만든다 | 금지 |
| `@ExceptionHandler` 추가 | 예외를 삼켜 **500을 200으로** 바꾼다. 상태 코드만 검사하면 통과다 | 🔴 **응답 본문을 기록하고 검사한다** + 증상 덮기 패턴이면 확신도를 내린다 |
| 경로에 `..`·심볼릭 링크 | 화이트리스트 밖으로 나간다 | `git apply` **전에** 실제 경로로 펴서 검사 |

그리고 검사 코드를 **`hindsight-guard` 라는 자기 모듈**로 뺐다 — 파일을 쓰는 유일한 통로로 만들어서
우회하려면 눈에 띄게 이상한 것을 import 해야 하게 했다.

⚠️ **평가할 수 없는 포트폴리오는 높은 점수가 아니라 0점을 받는다.**

**고친 것**: `demo-app` 에 일주일을 더 쓴다 — JPA 연관관계·트랜잭션·Redis·Docker Compose·
테스트·CI·OpenAPI. 포트폴리오가 두 겹이 된다: *"스프링 서비스를 만들었고, 그걸 디버깅하는
JVM 에이전트도 만들었다."*

### 선행 연구를 하나도 안 적었다

면접 첫 질문이 *"이거 Keploy 아니에요?"* 인데 문서에 답이 없었다.

**고친 것**: PRD에 비교표를 만들고 **「우리보다 나은 점」 열을 먼저** 뒀다.
Keploy·**ReCrash(2008)**·**테스트 카빙**·JFR·APM·Sentry Autofix·Undo.
🎯 Keploy에 대한 답은 이것이다 — *"소켓에서 잡으면 `Instant.now()` 가 안 보인다.
그래서 재생이 얼마나 믿을 만한지를 잴 수 없다."*

**고친 것**: 심을 버그 목록을 **먼저 고정**하고, v2에서 **오픈소스 실제 이슈 3건**을 돌린다.

## 🔴 개인정보를 너무 낙관했다

처음 설계는 가명화하면 개인정보가 「사라진다」고 적었다. **아니다.**

- 개인정보보호법에서 가명처리한 값은 여전히 **가명정보**이고 **개인정보다**
- 미국 LLM 제공자에게 보내는 것은 **국외이전**이다
- HMAC은 값의 범위가 좁으면(전화번호·한국 이름) **대조로 되돌릴 수 있다.**
  키가 기록과 같은 컴퓨터에 있으면 더욱

**고친 것**: 「가명정보는 익명정보가 아니다」 절(§9-1)을 넣었다. 가명화는 법적 면책이 아니라
겹으로 쌓는 방어의 한 겹이고, **데모와 공개 기록은 전부 합성 데이터만** 쓴다.
LLM으로 보낼 때는 **허용 목록** 방식도 함께 둔다 — 모르는 JSON에 대한 금지 목록은 언젠가 샌다.

## 등급 체계가 **주장이었지 실측이 아니었다**

`DETERMINISTIC` 을 「어떤 계측이 걸렸나」로 미리 매기고 있었다. 그런데 캐시가 따뜻했는지,
정적 변수에 뭐가 쌓였는지는 계측 목록으로 알 수 없다.

**고친 것**: 🎯 **재생 중에도 같은 계측을 켜고 실제 경계 호출을 기록과 대조한다.**
전부 맞으면 `VERIFIED_DETERMINISTIC`(관찰이지 약속이 아니다), 안 맞으면 `DIVERGED`.
**이 한 장치가 등급 문제와 §6-2의 정책을 동시에 푼다.** 이게 이 프로젝트에서 기술적으로
가장 흥미로운 부분이고 포트폴리오에서 앞세울 것이다.
