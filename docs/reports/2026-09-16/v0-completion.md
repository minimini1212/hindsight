## 2. 🎯 채점 네 겹이 «넷 다» 돌았다

### 무엇이 빠져 있었나

판단 코드(`VerificationLoop`)는 2026-09-15 에 생겼고 순수 함수라 전수로 시험됐다.
그런데 **그 판단에 진짜 결과를 넣어 준 적이 없었다.** ㉠㉡ 만 진짜로 돌았고,
㉢(앱의 기존 테스트)과 ㉣(되돌리기)은 **돌릴 것이 없는 겹**이었다.

🔴 **㉢ 이 돌 수 없었던 이유가 이번에 드러났다** — 이 앱의 시험 12개가 **전부 Hindsight
실험**이었다. 「앱이 원래 갖고 있던 테스트」가 한 개도 없었으므로, ㉢ 은 처음부터
**깨질 수 있는 것이 없는 검사**였다.

### 잰 값

```
── 실험 ⑭-① 진짜 고침 ──
확신도: 중간 — 재현 테스트와 진단만 주고, 패치는 초안으로 붙인다
경로: ALLOW (전부 화이트리스트 안이다: src/main/java/)
㉠ 기준선 실패      통과
㉡ 검증 통과        통과
㉢ 앱의 기존 테스트  통과
㉣ 되돌리기         통과
  · 재생 등급을 안 봤다. 자동으로 올리지 않는다
  발자국:
    재생 테스트: 돌았나=true 통과했나=false (같은 모양의 질의가 5번 반복되던 것이 그대로면…)
    패치 적용 (join fetch 로 갈아탄다)
    재생 테스트: 돌았나=true 통과했나=true
    기존 테스트: 5/5 통과
```

🔴 **네 겹이 다 통과했는데도 확신도가 「중간」이다.** 재생 등급을 안 봤기 때문이다 —
「안 본 것」이 「괜찮았다」로 올라가지 않는 것을 여기서 확인했다.

### ㉢ 이 진짜로 «막는지» 따로 봤다

```
── 실험 ⑭-② 앱을 깨뜨리는 패치 ──
㉠ 기준선 실패      통과
㉡ 검증 통과        통과      ← 🔴 재생 테스트는 통과했다
㉢ 앱의 기존 테스트  실패
㉣ 되돌리기         안 돌렸다  ← 🔴 「통과」가 아니다
```

⚠️ **㉡ 이 통과했다는 것이 이 실험의 핵심이다.** 「질의를 덜 했나」만 보면 이 패치는
나간다. ㉢ 이 없으면 **하나 고치고 다른 것을 깨뜨린 패치가 PR 로 올라간다.**

### ㉣ 이 진짜로 «되돌리는지» 손으로 확인했다

고리가 스스로 「되돌렸다」고 말하는 것과 진짜로 되돌아간 것은 다른 사실이라,
고리를 거치지 않고 직접 봤다.

```
㉠ 패치 전  → 실패
㉡ 패치 후  → 통과
㉣ 되돌린 뒤 → 실패   ← 여기서 통과하면 ㉡ 의 「통과」가 아무 뜻이 없다
```

### ⬜ 이 실험이 증명하지 «않는» 것

⚠️ 「패치」는 여전히 **설정 한 줄**이다(`setNPlusOneFixedForTest`). 진짜 도구에서는
LLM 이 소스를 고치고 `PatchApplier` 가 파일을 쓴 뒤 앱을 다시 띄운다.
🔴 **그래서 이것이 보이는 것은 「네 겹이 도는가」이지 「LLM 이 고칠 수 있는가」가 아니다.**

다만 ㉣ 만큼은 진짜다 — 되돌리면 앱의 동작이 실제로 되돌아간다.

## 3. 🔴 `hs` 를 진짜 콘솔에서 처음 돌렸다 — 그리고 세 군데서 막혔다

여기까지 `hs` 는 **클래스로만** 있었다. 시험 안에서는 돌지만 사람은 못 쓴다.
그리고 사람이 못 쓰면 **사람이 쓸 때 무엇이 깨지는지도 영영 모른다.**

돌려 보니 벽이 셋이었다.

| 무엇 | 어떻게 보였나 |
| --- | --- |
| `.bat` 의 줄바꿈이 LF | `'HIS' is not recognized as an internal or external command` |
| `.bat` 의 한글 | `'??' is not recognized as an internal or external command` |
| `hs.jar` 이 자바 21 필요 | `class file version 65.0` — 「자바를 올려라」라고 말하지 않는다 |

🧭 자세히: [배치파일을 돌리면 주석 조각이 명령으로 실행된다](troubleshooting/배치파일을-돌리면-주석-조각이-명령으로-실행된다.md)

## 4. 🔴 PR 이 나가기 직전에 한 번 더 훑는다

### 왜 가명화가 있는데 또 보나

가명화는 **기록의 정해진 자리**(헤더 · 본문 · 질의 파라미터)를 훑는다.
그런데 PR 본문은 그 기록에서 **글을 지어낸 것**이라, 가명화가 훑지 않은 자리에서
값이 흘러나올 수 있다. 그리고 PR 본문은 **저장소 밖으로 나가는 유일한 글**이다 —
올라가면 못 되돌린다(지워도 알림 메일과 색인에 남는다).

### ⚠️ 시험이 내 가정을 틀렸다고 말했다

처음에는 **예외 메시지**에 이메일을 넣어 시험했다. 그런데 안 걸렸다 —
**예외 메시지는 PR 본문에 아예 안 실린다.** 타입만 실린다.

🔴 즉 그 경로로는 애초에 안 샜다. 실제로 새는 자리는 **진입점 경로 · 질의문 ·
생성된 테스트가 못 단언한 것**처럼 글에 그대로 옮겨 적는 곳이다.

### ⚠️ 그리고 「막기만」 해서는 부족했다

처음 판은 모양이 걸리면 **자동으로 여는 것만** 멈췄다. 시험이 바로 잡았다 —
**본문에는 원본이 그대로 남아 있었다.** 사람이 읽어 보고 손으로 열면 그대로 나간다.
PR 본문은 복사해서 붙이라고 만든 글이라 더 그렇다.

지금은 **막고, 본문에서도 가린다.** 조용히 지우지는 않는다.

```
`GET /api/users/hon********com/orders?phone=010*******678` 에서 3400ms 가 걸렸다.

## 나가기 전 한 번 더 훑었다

🔴 **개인정보 모양이 2건 걸렸다. 그래서 이 PR 은 자동으로 열리지 않고,
   아래 값은 본문에서도 가렸다.**

- 이메일 — 가리기 «전» 본문의 28번째 글자쯤 (`hon********com`)
- 휴대폰 번호 — 가리기 «전» 본문의 66번째 글자쯤 (`010*******678`)

⬜ **모양으로는 못 찾는 것**:
- 사람 이름 · 주소 · 회사 이름 — 모양이 없다
- 주문 내용 · 상품명 — 그 자체로는 평범한 글자다
- 내부 호스트 이름 · 사설 IP — 새는 건 맞지만 개인정보는 아니라 여기서 안 본다
```

🔴 **「못 찾는 것」이 항상 같이 나간다.** 없으면 「훑었으니 안전하다」로 읽히는데,
그게 이 프로젝트가 잡으려는 결함이다. 그 한계를 **시험으로도 못 박았다** —
`홍길동 님이 서울시 강남구로 주문했다` 는 **안 걸린다**는 것을 단언으로 적어 뒀다.

### 본문 길이 상한

GitHub 의 본문 상한은 65,536자다. 넘으면 API 가 거절하는데, 그 실패는 「PR 을 못 열었다」로만
보이고 원인이 길이라는 것은 안 보인다. 60,000자에서 자르되 **잘랐다는 사실과 원래 길이를
본문에 적는다** — 조용히 짧아지면 「원래 이만큼이었다」로 읽힌다.

## 5. 시도 3회 · 비용 상한

### 왜 둘 다인가 — 하나만 끊으면 안 끊긴다

```
횟수만 끊으면 │ 3번째 시도가 40만 토큰짜리일 수 있다. 상한이 사실상 없다
돈만 끊으면   │ 싼 모델로 200번 돌 수 있다. 200번 실패한 것은 못 고치는 것이다
```

🔴 **「예산을 다 썼다」를 「못 고쳤다」로 적지 않는다.** 같게 다루면
「LLM 이 못 고쳤다」는 결론이 나오는데, 실제로는 한 번도 제대로 못 시켜 본 것일 수 있다.

세 자리에서 「모름」을 「없음」으로 안 접는다.

| | 어떻게 다루나 | 왜 |
| --- | --- | --- |
| 다음 호출 비용을 모름 | **거절한다** | 0 으로 치면 상한이 없는 것과 같다 |
| 실제로 든 비용을 모름 | **상한만큼 썼다고 친다** | 0 으로 적으면 예산이 영영 안 준다 |
| 상한 0 | **「공짜만 허용」** | 「무제한」으로 읽으면 설정 실수 하나가 청구서가 된다 |

🔴 그리고 **부르기 «전»이 아니라 «부른 뒤»에 센다.** 부르기 전에 세면 호출이 터졌을 때도
시도를 깎고, 그러면 네트워크가 나쁜 날 LLM 을 **한 번도 못 불러 보고** 「세 번 실패」가 된다.

⚠️ 이 클래스는 **LLM 을 부르지 않고 돈도 세지 않는다.** 쓴 만큼을 밖에서 받아 적을 뿐이다.
그래서 「상한이 진짜로 끊나」를 확인하려고 진짜 돈을 쓸 필요가 없다.

## 6. ⬜ 무엇이 아직 확인 안 됐나

### 🔴 사람이 넣어 줘야 풀리는 것 셋 — v0 완료 조건을 막고 있다

| 무엇 | 왜 |
| --- | --- |
| **LLM 진단** | API 키가 `.env` 에 있어야 한다. 🔴 Claude 는 `.env` 를 안 쓴다 |
| **PR 실제 제출** | `gh auth login` 이 브라우저·코드 입력이라 비대화형으로 못 끝낸다 |
| **demo-app 을 「진짜 서비스」로** | 범위를 얼마나 키울지는 **판단**이다 |

### 그 밖에

- 🔴 **「LLM 이 고칠 수 있는가」는 여전히 모른다.** 위의 모든 실험에서 「고친 코드」는
  사람이 미리 써 둔 것이다
- **패치를 «파일로» 적용하고 앱을 다시 띄우는 경로가 없다.** 지금은 설정 한 줄로
  갈아탄다. ⬜ 다시 띄우는 비용을 **안 쟀다**
- ⬜ **`hs` 를 구형 conhost 에서 안 봤다.** 기록이 수백 건일 때 어떻게 보이는지도 안 봤다
- ⬜ **유출 검사는 «모양이 있는 것»만 본다.** 사람 이름 · 주소 · 상품명은 못 찾는다.
  이건 고칠 수 있는 결함이 아니라 **이 검사의 한계**이고, 그래서 결과에 같이 나간다
- ⬜ **가린 뒤의 본문 글자 위치가 밀린다.** 보고에 적히는 번호는 «가리기 전» 기준이라
  「그쯤」이라고만 말한다
- ⬜ **비용을 실제로 재 본 적이 없다.** `AttemptBudget` 은 밖에서 받은 숫자를 더할 뿐이고,
  그 숫자를 채워 줄 코드가 아직 없다
- ⬜ **동시 요청에서의 기록기 오버헤드**는 여전히 안 쟀다. 지금까지 전부 한 스레드다
