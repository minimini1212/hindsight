# 채점 결과를 PR 로 — 그리고 «눈으로 읽어 보니» 기록의 구멍이 통째로 빠져 있었다

> 2026-09-16. v0 4주차.
> PR 이 무엇을 담아야 하는지는 [설계](../../DESIGN.md)의 「제출 — 배포는 하지 않는다」 절(§8)에 있다.

---

## 1. 무엇이 생겼나

**채점 결과를 사람이 읽고 판단할 수 있는 PR 글로 바꾼다.**
🔴 PR 을 «열지» 않는다. 배포는 말할 것도 없다 — 글자만 만든다.
그래서 이 판단은 **네트워크 없이 전수로 확인된다.**

| | 전 | 후 |
| --- | --- | --- |
| 검사 | 192건 | **208건** (core 136 · recorder 43 · demo-app 29) |
| 자바 파일 | 83개 | **87개** |

### 본문이 항상 담는 셋

| | |
| --- | --- |
| 무엇이 있었나 | 포획된 상황 · 방아쇠 · 진입점 · **몇 번 났나** |
| 무엇을 확인했나 | 생성된 테스트와 **그 오라클** · 네 겹 · 재생 등급 · 시도 횟수 |
| 🔴 무엇을 확인하지 **못했나** | 단언 못 한 자리 · 안 돌린 겹 · 못 잡은 것 · **기록의 구멍** |

---

## 2. 🔴 제목이 확신도를 숨기지 않는다

```
높음   fix(hindsight): GET /api/orders 의 사고를 고쳤다 — 재생으로 확인함
중간   🟡 [초안] GET /api/orders — 진단과 재현 테스트. 패치는 사람이 본다
낮음   🔴 [사람 필요] GET /api/orders — 자동으로 못 고쳤다. 기록과 테스트만 남긴다
```

PR 제목은 **목록에서 「본문 없이」 읽히는 자리**다. 확신도가 「중간」인데 제목이
「고쳤습니다」면, 본문을 안 읽는 사람에게는 **거짓말**이 된다.

✅ **일부러 숨기게 만들어 확인했다** — 중간일 때도 「고쳤다」로 적게 바꾸니 검사가 실패했고,
되돌리니 통과했다.

---

## 3. 🔴 «눈으로 읽어 보니» 둘이 나왔다

조각조각 단언하는 검사 15건은 **전부 통과**하고 있었다. 그런데 만들어진 PR 을
**통째로 찍어서 읽어 보니** 둘이 보였다.

### ① 등급이 두 번 찍혔다

```
등급 **DIVERGED** · DIVERGED · 오라클 1/2 통과
```

요약 문자열이 이미 등급으로 시작하는데 앞에 또 붙이고 있었다. 사소하지만,
**각 조각을 단언하는 검사로는 절대 안 잡힌다** — 조각은 둘 다 맞기 때문이다.

### ② 🔴 기록이 이벤트 17건을 버렸는데 PR 에 그 말이 없었다

이게 진짜다. 시험에 쓴 기록은 **큐가 차서 17건을 못 받았고**, 담으려던 60초 중
**4.2초만 담겼다.** 그런데 PR 본문에는 **한 글자도 없었다.**

**왜 빠졌나**: 기록의 구멍은 재생 등급이 `PARTIAL` 일 때 `missing` 에 실려 나간다.
그런데 이 경우 등급이 `DIVERGED` 라서 **`PARTIAL` 경로를 안 탔고**, 그래서 통째로 사라졌다.

🔴 **버려진 그 17건 중에 사고의 원인이 있었을 수 있다.** 그걸 모른 채 머지하는 것과
알고 머지하는 것은 다른 일이다.

**고침**: 기록의 구멍을 **재생 등급과 별개로** 항상 적는다 — 두 개는 다른 축이다.

```
- ⬜ 기록할 때 큐가 차서 **17건을 못 받았다**. 그중에 원인이 있었을 수 있다
- ⬜ 담으려던 60초 중 실제로는 **4.2초만 담겼다** — 그 앞에서 시작된 일은 이 기록에 없다
```

### 🧭 여기서 배운 것

> **조각을 단언하는 검사만 있으면, 각 조각은 맞는데 «합쳐 놓으면 틀린» 것이 나온다.**

그래서 만들어진 PR 을 **통째로 출력하는 시험**을 남겼다. 그리고 눈으로 찾은 둘을
그 시험의 단언으로 **못 박았다** — 눈으로 찾은 것을 눈에만 두면 다음에 또 놓친다.

---

## 4. 🔴 「확인하지 못한 것」 목록은 «비지 않는다»

네 겹 전부 통과, `missing` 비어 있음, 판정 못 한 것 없음 — **그래도 비우지 않는다.**
그때는 **재생이 원래 증명하지 않는 것**을 적는다.

```
- ⬜ **재생은 이 상황 하나만 본다.** 다른 상황에서도 되는지, 무엇이 더 깨졌는지는
     증명하지 않는다 — 경계 «안쪽»만 보기 때문이다
- ⬜ **앱 안에 쌓인 상태**(캐시 · 정적 변수 · 세션)는 되돌리지 않았다
```

아무 말이 없으면 읽는 사람은 **「전부 확인됐다」로 읽는다** — 그리고 그건 사실이 아니다.

---

## 5. 🔀 `DIVERGED` 가 가장 좋은 PR 설명이 되는 자리

제대로 고칠수록 재생이 깨진다. 그때 「채점 불가」라고만 하면 쓸모가 없으므로,
**무엇이 무엇으로 바뀌었는지**를 붙인다.

```
before  select * from member where id = ?   20번
after   select o.*, m.* from orders o join member m on o.member_id = m.id   1번

질의 20개가 1개로 줄었다. N+1 해소와 부합한다
```

## 6. ⬜ 무엇이 아직 확인 안 됐나

- 🔴 **PR 을 실제로 올려 본 적이 없다.** 글자만 만들고, GitHub 에 보내는 코드는 없다
- **LLM 을 부르는 코드가 없다.** 그래서 「시도 횟수」는 아직 «항상 1» 이고,
  진짜 재시도를 겪어 본 적이 없다
- **패치를 브랜치로 만들고 커밋하는 코드가 없다.** 지금은 파일을 쓰는 데까지만 있다
- 🔴 **본문에 원본 데이터가 새지 않는지는 «가명화가 이미 됐다»는 데 기대고 있다.**
  기록은 디스크에 쓰기 전에 가명화되므로 그 기록에서 읽은 값은 안전하지만,
  ⬜ **PR 본문을 따로 훑어 확인하는 검사는 없다**
- **본문 길이 상한이 없다.** 이벤트가 많은 기록이면 PR 이 아주 길어질 수 있는데,
  ⬜ 얼마나 길어지는지 **안 쟀다**
