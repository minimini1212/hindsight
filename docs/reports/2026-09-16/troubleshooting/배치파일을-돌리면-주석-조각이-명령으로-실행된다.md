# `bin\hs.bat` 을 돌렸더니 주석 조각이 「명령」으로 실행된다

> 2026-09-16. 증상 그대로 적는다 — 원인을 알았으면 검색하지 않았을 것이므로.

---

## 1. 무엇이 보였나

방금 만든 배치 파일을 처음 돌렸는데 이렇게 나왔다.

```
'HIS' is not recognized as an internal or external command,
operable program or batch file.
'le's' is not recognized as an internal or external command,
'ytes' is not recognized as an internal or external command,
'ognized' is not recognized as an internal or external command,
```

🔴 **`HIS` · `ytes` · `ognized` 는 전부 내가 쓴 «주석»의 조각이다.**
`THIS FILE IS ASCII-ONLY` 의 `HIS`, `bytes` 의 `ytes`, `recognized` 의 `ognized`.

그 앞에는 이렇게도 나왔다.

```
'��' is not recognized as an internal or external command,
```

---

## 2. 원인은 «둘»이고, 둘 다 있어야 한다

### ① 줄바꿈이 LF 뿐이었다 — 이게 진짜 원인

`cmd.exe` 는 배치 파일을 **CRLF 로 끊어 읽는다.** LF 뿐이면 줄을 엉뚱한 자리에서 자르고,
잘린 조각을 **명령으로 실행하려 한다.** 그래서 `rem` 으로 시작한 줄인데도
그 줄의 중간 토막이 명령이 된다.

```
전: CRLF 0줄 · LF만 70줄     ← 여기서 깨졌다
후: CRLF 70줄 · LF만 0줄     ← 돈다
```

### ② 주석에 한글이 있었다 — 이건 «따로» 있는 문제

`cmd` 는 배치 파일을 **콘솔 코드페이지**로 읽는다. UTF-8 로 저장한 한글은 그 눈에
깨진 바이트로 보이고, 역시 명령이 된다. 위의 `'��' is not recognized` 가 그것이다.

⚠️ **①만 고치면 ②가 남는다.** 실제로 CRLF 로 바꾸고 나서도 한글 주석 한 줄 때문에
`'�글이-명령으로-실행된다.md' is not recognized` 가 계속 나왔다.

---

## 3. 🔴 안 통한 길 — 「`.gitattributes` 에 이미 있는데?」

저장소에는 이미 이렇게 적혀 있었다.

```
*.bat text eol=crlf
```

**그런데 안 막혔다.** 그 설정은 **git 을 «거칠 때»** 고쳐 준다 —
체크아웃하면 CRLF 로 내려오고, 커밋하면 LF 로 담긴다.
🔴 **방금 «만든» 파일은 아직 git 을 안 거쳤다.** 작업 트리에 LF 로 앉아 있고,
내가 돌리는 것은 그 파일이다.

⚠️ 그러니까 `.gitattributes` 는 **다음 사람**을 지켜 주지, **만든 사람**은 안 지켜 준다.
그리고 만든 사람이 「돌려 봤더니 안 되네」를 겪는 자리가 바로 여기다.

---

## 4. 어떻게 고쳤나

**둘 다 고치고, 빌드가 지키게 했다.**

1. `bin/hs.bat` 을 **CRLF + ASCII 전용**으로 다시 썼다
2. 하고 싶은 한글 설명은 **자바 쪽으로 옮겼다** — 거기는 UTF-8 이 끝까지 간다
3. `checkLauncherScripts` 라는 Gradle 검사를 만들어 `check` 에 걸었다

검사는 이렇게 본다.

```
bin/*.bat  →  CRLF 인가 · ASCII 인가
bin/hs     →  CRLF 가 «없는»가   (셔뱅 뒤의 \r 때문에 「해석기를 못 찾겠다」가 난다)
```

✅ **세 가지로 일부러 깨뜨려서 잡히는 것을 확인했다.**

```
a) .bat 을 LF 로       → BUILD FAILED
b) .bat 에 한글 한 줄  → BUILD FAILED
c) bin/hs 를 CRLF 로   → BUILD FAILED
d) 되돌린 뒤          → BUILD SUCCESSFUL
```

## 5. 같이 나온 것 — `hs.jar` 이 자바 17 에서는 아예 안 뜬다

배치 파일이 고쳐지자 다음 벽이 나왔다.

```
java.lang.UnsupportedClassVersionError: io/hindsight/core/cli/HindsightCli
has been compiled by a more recent version of the Java Runtime
(class file version 65.0), this version of the Java Runtime only
recognizes class file versions up to 61.0
```

`hindsight-core` 는 **자바 21**로 컴파일된다(65.0). 그런데 이 저장소에서 빌드할 때 쓰는
`JAVA_HOME` 은 **17**(61.0)이다 — 툴체인이 모듈마다 알아서 골라 주기 때문에
빌드는 되는데, **손으로 jar 를 돌리면 안 뜬다.**

🔴 **그 메시지는 「자바 21 을 깔아라」라고 말하지 않는다.** 숫자만 말한다.
그래서 `bin/hs.bat` 이 실패한 «뒤»에 사람 말로 덧붙이게 했다.

### ⚠️ 여기서도 한 번 틀렸다 — `java -version` 을 파싱하려다 «조용히» 통과시켰다

처음에는 배치 파일 안에서 버전을 미리 읽어 막으려 했다. `for /f` 와 지연 확장이
얽혀서 `HS_MAJOR` 가 빈 값이 됐고, **가드가 그냥 통과했다.**
자바 17 이 jar 까지 도달해서 똑같이 죽었는데, 겉보기엔 가드가 있는 것처럼 보였다.

🔴 **조용히 아무것도 안 하는 가드는 없는 가드보다 나쁘다.** 그래서 파싱을 버리고,
**돌려 보고 실패하면 설명을 붙이는** 쪽으로 바꿨다.
