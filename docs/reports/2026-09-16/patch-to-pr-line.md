# 패치에서 PR 까지 한 줄로 이었다 — 그리고 「같은 답이 세 번 오는」 자리를 막았다

> 2026-09-16. v0 4주차. 어제까지 조각은 다 있었는데 **서로를 몰랐다.**
> 이 글은 그 조각들을 잇는 자리와, 잇다가 드러난 것들이다.

---

## 2. 🔴 「왜 실패했는지」를 다시 알려 주는 것이 이 고리의 핵심이다

그냥 세 번 물으면 **같은 답이 세 번 온다.** LLM 은 자기가 방금 뭘 틀렸는지 모른다 —
우리가 말해 줘야 다음 시도가 **「다른」 시도**가 된다.

⚠️ 안 그러면 **「세 번 시도했다」가 실은 「한 번을 세 번 반복했다」**가 되고,
그 뒤에 나오는 「LLM 이 못 고쳤다」는 근거가 없는 결론이 된다.

네 겹 중 **어디서** 걸렸는지가 다음 시도의 유일한 새 정보다.

| 걸린 자리 | 다음 시도에 들려 보내는 말 |
| --- | --- |
| ㉠ 기준선 실패 | 「그 테스트로는 이 버그를 못 잡는다 — 기록에 남은 증상을 다시 본다」 |
| ㉡ 검증 통과 | 「적용해도 여전히 실패했다. 증상이 그대로다」 |
| ㉢ 기존 테스트 | 「증상은 고쳤지만 **앱의 기존 테스트를 깨뜨렸다**」 |
| ㉣ 되돌리기 | 「되돌려도 통과했다. 그 테스트는 패치와 **무관**하게 통과하던 것이다」 |
| 경로 검사 | 「**경로 때문에** 거절됐다: (판정 내용)」 |

---

## 3. 🔴 멈출 때 «왜» 멈췄는지를 구별한다

| 상황 | 예산을 깎나 | 결과 |
| --- | --- | --- |
| 예산이 없다 | — | LLM 을 **한 번도 안 부른다** |
| LLM 을 못 불렀다 (키 없음 · HTTP 실패) | ❌ **안 깎는다** | 거기서 끝. 다시 물어도 같다 |
| 패치를 못 받았다 | ✅ 깎는다 | 형식을 알려 주고 다시 |
| 경로에 걸렸다 | ✅ 깎는다 | 🔴 **적용도 안 하고**, 채점은 `null`(안 돌렸다) |
| 네 겹에서 걸렸다 | ✅ 깎는다 | 어디서 걸렸는지 들려 보내고 다시 |

🔴 **「예산이 끝났다」를 「못 고쳤다」로 적지 않는다.**

```
"여기까지만 해 보기로 했다 (시도 2/2 · 비용 0/100센트)"
```

그리고 🔴 **경로에 걸렸을 때 채점을 「다 실패」로 적지 않는다.**
적용조차 안 했으므로 **안 돌린 것**이고, `null` 이 그 사실이다.

## 4. 🔴 진짜로 파일을 쓰고, 진짜로 다시 빌드한다

여기까지의 모든 실험은 **설정 한 줄**로 「패치」를 흉내 냈다. 진짜 패치는 소스를
고치는 것이고, **고친 소스는 다시 컴파일해야 돈다.**

🔴 그런데 **돌고 있는 JVM 안에서는 그게 안 된다.** 이미 로딩된 클래스를 못 갈아 끼운다.
그래서 **바깥 프로세스로 Gradle 을 부른다.**

```
패치를 파일로 쓴다 (PatchApplier — 경로 검사가 그 «안»에 있다)
  → ./gradlew :demo-app:test 를 «새 프로세스»로 부른다
    → 그 프로세스가 컴파일하고 테스트를 돌린다
```

⚠️ **느리다.** 한 번 돌 때마다 컴파일 + 스프링 기동이 들어간다. 시도 세 번이면 세 번이다.
🔴 그런데 **「빠르게 하려고 JVM 안에서 흉내 내는」 길은 「고쳤다」를 증명하지 못한다** —
컴파일이 안 되는 패치도 통과해 버린다.

### ㉢ 은 «앱 자신의» 테스트만 돌린다

```
./gradlew :demo-app:test --tests "io.hindsight.demo.order.*"
```

도구의 시험까지 돌리면 **이 고리가 자기 자신을 다시 부른다**(재귀).
그리고 「도구가 스스로를 검사한 것」을 「앱이 안 깨졌다」로 읽게 된다.

## 5. 🔴 쓰다가 내가 만든 구멍을 하나 찾았다

`RealFixer` 를 쓰다가, `패치를_적용한다()` 를 **다시 붙이지 못하게** 만들어 놓은 것을 봤다.

```
네 겹의 ㉣ 은 「되돌리면 다시 실패하나」를 본 뒤,
통과하면 패치를 «다시 붙여 둔다» — 그래야 그 뒤에 PR 이 그 상태를 커밋한다.
```

🔴 **다시 못 붙이면 ㉣ 이 통과한 「고친 상태」가 되돌려진 채로 남고,
PR 이 «패치 전» 코드를 올린다.** 네 겹을 다 통과했다고 적힌 PR 이 아무것도 안 고친 것이다.

지금은 패치를 들고 있다가 다시 붙이고, 그걸 시험으로 못 박았다.

---

## 6. 🔴 이 코드는 «사람의 작업 트리»를 고친다

그래서 시험이 지켜야 할 것이 하나 더 있다 — **끝나고 나면 아무것도 안 바뀌어 있어야 한다.**

```
✅ 패치를 진짜로 파일에 쓴다
✅ 되돌리면 «글자까지» 원래대로다
✅ 🔴 «원래 없던» 파일은 되돌릴 때 «지운다» — 빈 파일로 남기면 다음 빌드가 깨진다
✅ ㉣ 뒤에 다시 붙일 수 있다
✅ 🔴 테스트 파일을 고치려 들면 «아무것도 안 쓰고» 거절한다
✅ 🔴 거절됐으면 «되돌릴 것도 없다» — 되돌리기가 멀쩡한 파일을 덮지 않는다
```

그리고 전체 빌드 뒤 `git status` 가 **비어 있는 것**을 확인했다.

---

## 7. 🔴 PR 은 «만들기만» 한다

고리는 PR **글**까지 만들고 멈춘다. 올리는 것은 `core.ship` 이 하고, 그건 토큰이 있어야 한다.

⚠️ 둘을 한 클래스에 두면 **「만들었는데 안 올렸다」를 시험할 수 없다.**

그리고 **몇 번 만에 나온 패치인지가 PR 본문에 적힌다** —
세 번 만에 나온 패치와 한 번에 나온 패치는 다른 사실이다.

## 8. ⬜ 무엇이 아직 확인 안 됐나

- 🔴 **이 고리를 «진짜 LLM 으로» 끝까지 돌려 본 적이 없다.** 조각은 각각 진짜로 돌았지만
  (LLM 호출 ✅ · 파일 쓰기 ✅ · 바깥 Gradle 호출 ✅), **셋을 한 번에 이어서는 안 돌렸다.**
  ⬜ 한 판이 몇 분 걸리는지, 진짜로 고쳐지는지 **모른다**
- ⬜ **PR 을 진짜로 올려 본 적이 없다.** `GITHUB_TOKEN` 이 없어 전부 연습이다
- ⬜ **재생 테스트를 `BaselineFailsTest` 로 대신 돌린다.** 그건 기록에서 테스트를 만들어
  돌리는 시험이지, **이 패치에 맞춰 만든 재생 테스트**가 아니다 —
  🔴 즉 ㉠㉡ 가 「이 패치」를 보는지는 아직 느슨하다
- ⬜ **시도마다 전체 빌드가 돈다.** 한 모듈만 돌리는 길이 있는지 안 봤다
- ⬜ **다른 버그 모양에서 안 해 봤다.** N+1 하나뿐이다
