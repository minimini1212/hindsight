# 과적합을 막는 네 겹 — 그리고 「왜 중간인지」가 사라지던 자리를 잡았다

> 2026-09-15. v0 4주차.
> 네 겹이 무엇을 막는지는 [설계](../../DESIGN.md)의 「과적합을 막는 네 겹」 절(§7-2)에 있다.

---

## 1. 무엇이 생겼나

**패치 하나를 네 겹으로 채점하고, 그 결과를 「무엇을 해도 되는가」로 바꾸는 코드.**
🔴 LLM 을 부르지 않고 파일도 안 쓴다 — 테스트를 어떻게 돌리는지도 모른다.
전부 밖에서 받으므로 **JVM 을 계측 아래 띄우지 않고 전수로 확인된다.**

| | 전 | 후 |
| --- | --- | --- |
| 검사 | 177건 | **192건** (core 120 · recorder 43 · demo-app 29) |
| 자바 파일 | 77개 | **83개** |

### 왜 네 겹인가

**화이트리스트는 채점표를 «지킬» 뿐, 채점을 «옳게» 만들지 않는다.**
패치가 테스트를 못 고치게 막아 놔도, **테스트 자체가 버그를 못 살리면** 아무 의미가 없다.

```
0. 경로 검사      건드리면 안 되는 자리인가        ← 걸리면 «아무것도 안 돌린다»
㉠ 기준선 실패     패치 «전»에 정말 실패하나         ← 걸리면 «LLM 을 부르지 않는다»
㉡ 검증 통과       패치 «후»에 통과하나
㉢ 기존 테스트     원래 있던 테스트가 다 통과하나     ← 🔴 고리 «안»에서
㉣ 되돌리기       되돌리면 «다시 실패»하나
```

---

## 2. 🔴 각 겹이 무엇을 막나

### ㉠ 이 맨 앞인 이유

생성된 테스트가 패치 전에도 통과하면 **패치 전에도 초록불, 패치 후에도 초록불**이다.
그런데 도구는 「통과했다」며 **아무것도 안 고친 패치로 PR 을 올린다.**
그래서 여기서 멈추고 **LLM 을 아예 부르지 않는다** — 패치를 적용해 보지도 않는다.

### 🔴 ㉢ 을 고리 «밖»에 두면 안 된다

처음 설계는 앱의 기존 테스트를 「PR 이후 CI 에서 돌린다」로 뒀다. 그러면
**프로젝트의 진짜 테스트를 한 번도 안 돌린 패치로 PR 이 자동 생성된다.**
CI 가 빨간불을 켜는 것은 그 PR 이 이미 올라간 «뒤»다.

### ㉣ 이 잡는 것

㉠~㉢ 이 다 통과해도, 그 테스트가 **패치와 아무 상관 없이** 통과하던 것일 수 있다.
되돌렸는데도 여전히 통과하면 **그 패치가 무엇을 고쳤는지 아무도 모른다.**

---

## 3. 🔴 「안 돌렸다」를 「통과」로 접지 않는다

겹의 결과가 셋이다 — 통과 · 실패 · **안 돌렸다**.

앞 겹에서 끝나 버리면 뒤 겹은 「안 돌렸다」로 남는다. 여기를 `true` 로 채우면
**확인한 적 없는 것을 확인했다고 적는 것**이다. 그리고 요약은 **안 돌린 겹을 항상 보여 준다** —
통과한 것만 보여 주면 읽는 사람은 그게 전부라고 믿는다.

```
확신도: 낮음 — 기록과 테스트만 남기고 사람을 부른다
㉠ 기준선 실패      실패
㉡ 검증 통과        안 돌렸다
㉢ 앱의 기존 테스트  안 돌렸다
㉣ 되돌리기         안 돌렸다
🔴 안 돌린 겹: ㉡ 검증 통과, ㉢ 앱의 기존 테스트, ㉣ 되돌리기
```

---

## 4. 🔴 네 겹을 다 통과하고도 나쁜 패치가 있다

예외를 넓게 잡아 삼키면 **테스트는 통과한다.** 재시도를 붙이거나 타임아웃을 늘려도 통과한다.
그런데 그건 **고친 것이 아니라 안 보이게 한 것**이다.

채점으로는 이 둘을 가를 수 없다 — 통과는 통과다. 그래서 **패치의 «모양»을 본다.**

🔴 **다만 거절이 아니라 「사람이 본다」로 내리는 근거다.** 넓은 `catch` 가 정답인 경우도
실제로 있고, 그걸 자동으로 막으면 **옳은 패치를 벌주게 된다** —
이 프로젝트가 [설계 리뷰에서 이미 한 번 지적받은 실수](../2026-09-10/design-review.md)다.

### 🔴 원래 있던 것까지 세면 신호가 죽는다

`catch (Exception e)` 가 원래 있던 파일을 건드리면, **그 파일을 건드리는 모든 패치가
영원히 「사람이 본다」**가 된다. 늘 켜져 있는 경고등은 꺼져 있는 것과 같다.
그래서 **패치가 «새로 넣은» 것만** 센다(전후 개수를 견준다).

---

## 5. ⚠️ 만들다가 잡은 것 둘

### ① 「왜 중간인지」가 통째로 사라지고 있었다

확신도를 정하면서 이유를 적는데, 그 적는 대상이 **이미 굳은 목록**이었다
(`FourLayerScore` 가 `List.copyOf` 로 복사한 뒤였다). 그래서 보고서에는
**「중간」만 뜨고 왜 중간인지가 없었다.**

🔴 「모르겠다」고 말하는 것이 이 도구의 신뢰를 만드는데, **이유 없는 「모르겠다」는
아무 도움이 안 된다.** 확신도를 «먼저» 정하고 그다음 점수를 만들도록 순서를 뒤집었다.

### ② 내가 만든 검사가 flaky 였다

메모리 어림을 재는 검사가 **「5만 건이 전부 링에 담긴다」**를 단언하고 있었다.
그런데 큐가 차면 버리는 것은 이 설계의 **의도**다 — 빌드가 바쁜 날 실제로 **821건이 버려져**
검사가 깨졌다.

🔴 **가끔 실패하는 검사는 사람이 「또 그거네」 하고 넘기게 만들어 진짜 고장까지 같이 넘긴다.**
그래서 **보존**을 건다: *받아 준 것은 전부 링에 있어야 한다.*
이건 기계가 바쁘든 말든 참이어야 하고, 어긋나면 이벤트가 **설명 없이 사라진** 것이다.

✅ 전체 빌드를 **세 번** 돌려 통과를 확인했다.

---

## 6. 확신도 — 「높음」은 셋이 «전부» 맞아야 한다

| 확신도 | 조건 | 행동 |
| --- | --- | --- |
| **높음** | 네 겹 전부 통과 **＋** 재생 등급 `VERIFIED_DETERMINISTIC` **＋** 증상 덮기 없음 | PR 자동 생성 |
| **중간** | 재생이 `PARTIAL`·`DIVERGED` 이거나, 재생 등급을 «안 봤거나», 설정 파일을 고쳤거나, 증상 덮기가 보임 | 재현 테스트와 진단만. 패치는 초안으로 |
| **낮음** | 네 겹 중 하나라도 어긋남 | 기록과 테스트만 남기고 사람을 부른다 |

🔴 **재생 등급을 「안 봤으면」 높음이 안 된다.** 「괜찮았겠지」로 올리지 않는다.

---

## 7. ⬜ 무엇이 아직 확인 안 됐나

- 🔴 **진짜 앱으로 한 번도 안 돌렸다.** 이 판단이 옳은지는 «순서와 조합»의 문제라 앱 없이
  전수로 확인했지만, **「테스트를 돌린다」를 실제로 구현한 코드는 아직 없다**
- **LLM 을 부르는 코드가 없다.** 진단·패치 생성이 통째로 비어 있다 —
  API 키가 `.env` 에 있어야 하고, 그건 사용자가 넣는다
- **시도 3회 제한과 비용 상한이 없다.** 설계에는 있다(기록 하나당 $1)
- **PR 을 만드는 코드가 없다.** 네 겹의 결과를 본문으로 바꾸는 것까지만 있다
- **증상 덮기 검사가 «문자열»로 본다.** 주석이나 문자열 안의 단어에도 걸린다.
  🔴 그래서 거절이 아니라 「사람이 본다」인 것이다 — 거짓 양성이 사람의 시간을 조금 쓰는 것과,
  거짓 음성이 나쁜 패치를 자동 통과시키는 것은 값이 다르다.
  ⬜ 다만 **거짓 양성이 실제로 얼마나 나오는지는 안 쟀다**
