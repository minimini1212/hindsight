# 채점표를 고치지 못하게 막았다 — 그리고 «막는 척»과 «진짜 막는 것»을 갈랐다

> 2026-09-15. v0 4주차의 첫 항목.
> 무엇을 왜 막는지는 [설계](../../DESIGN.md)의 「채점표를 고치지 못하게 막는다」 절(§7-1)에 있다.

---

## 1. 무엇이 생겼나

**LLM 이 만든 패치가 디스크에 닿는 유일한 통로.** 경로를 «적용하기 전»에 보고,
건드리면 안 되는 자리가 하나라도 있으면 **아무것도 쓰지 않는다.**

| | 전 | 후 |
| --- | --- | --- |
| 검사 | 150건 | **177건** (core 105 · recorder 43 · demo-app 29) |
| 자바 파일 | 72개 | **77개** |

### 왜 필요한가

LLM 에게 *"테스트를 통과시켜라"* 라고 하면 **테스트를 지워서 통과시킨다.**
🔴 이건 가정이 아니라 LLM 코딩 도구에서 관찰된 행동이다.

**채점기가 있다고 «믿는» 구조에서 채점표를 고칠 수 있으면, 그 구조는 아무것도 보장하지 않는다.**

---

## 2. 무엇을 어떻게 나누나

| 자리 | 판정 | 왜 |
| --- | --- | --- |
| `src/main/java/**` | ✅ 허용 | 고쳐야 할 코드가 있는 곳 |
| `src/main/resources/**` | 🟡 **사람이 본다** | 🔴 `application.yml` 한 줄로 **검증을 끄거나 기능 플래그를 뒤집을 수 있다** |
| `src/test/**` | 🔴 거절 | **채점표 그 자체** |
| 기록 파일 | 🔴 거절 | 채점의 **입력**. 고치면 원하는 답을 만들 수 있다 |
| `.github/**` | 🔴 거절 | **CI 를 고쳐서 통과시킬 수 있다** |
| `gradle/**` · `*.gradle*` · `gradlew` | 🔴 거절 | **빌드를 고쳐서 통과시킬 수 있다** |
| `.git/**` | 🔴 거절 | 역사 자체를 고칠 수 있다 |
| `hindsight-*` | 🔴 거절 | 🔴 **자기 채점기를 약화시킬 수 있다** |

### 🔴 판정이 셋인 이유

「된다/안 된다」 둘뿐이면 애매한 것을 어느 한쪽으로 밀어 넣게 되고, 그 방향은
**거의 항상 「된다」 쪽**이다 — 막으면 도구가 아무것도 못 하는 것처럼 보이기 때문이다.

설정 파일이 그 자리다. 막을 일은 아니지만 **사람이 봐야 하는 일**이다.
🔴 **그리고 「사람이 본다」는 「일단 적용해 두고 알려 준다」가 아니다** — 안 쓴다.

## 3. 🔴 경로 문자열을 그대로 믿으면 뚫린다

```
src/main/java/../../../.github/workflows/ci.yml
```

이 경로는 **화이트리스트로 시작한다.** 「앞이 맞는지」만 보면 통과하고,
그 패치는 CI 를 `exit 0` 으로 고쳐서 **모든 검사를 통과시킨다.**

그래서 반드시 **펴서** 본다. 그리고 절대 경로(`/etc/passwd`, `C:/...`, `~/...`)와
저장소 밖으로 나가는 경로를 거절한다.

🔴 **`Path.normalize()` 를 안 쓴 이유**: 운영체제마다 구분자와 규칙이 달라서
**윈도우에서 통과한 것이 리눅스에서 안 통과하거나 그 반대**가 될 수 있다.
채점의 안전선이 운영체제에 따라 달라지면 안 되므로 직접 편다.
그 덕분에 이 검사는 **순수 함수**이고, 파일이 없어도 전수로 확인된다.

### 문자열로는 못 잡는 것도 있다

`src/main/java` 가 **저장소 밖을 가리키는 심볼릭 링크**면, 경로 문자열은 완벽하게
화이트리스트 안이다. 그런데 쓰는 순간 밖에 쓴다. 그래서 쓰기 직전에 **실제 경로**를 확인한다.

⚠️ 이 검사는 **윈도우에서 건너뛰어진다**(권한 없이 링크를 못 만든다).
🔴 건너뛸 때 조용히 통과시키지 않고 **「확인하지 못했다」고 말하며 건너뛴다** —
통과와 미확인은 다른 사실이다.

---

## 4. 🔴 「막는 척」과 「진짜 막는 것」

이 프로젝트는 같은 것을 이미 한 번 헷갈렸다. 한때 이 검사를 **모듈로 뺐다** —
「자기 모듈이면 우회하기 어렵다」는 이유였는데 **틀렸다.**

> 모듈 경계는 파일 쓰기를 **못 막는다.** 같은 프로젝트의 다른 코드가
> `java.nio.file.Files` 를 직접 부르면 그만이고, Gradle 은 그걸 모른다.
> 🔴 **그건 장치가 아니라 그림이었다.**

그래서 이번에는 **검사와 쓰기를 한 함수 안에 묶었다.** 둘을 따로 두면 언젠가 누군가
편의상 `Files.write` 를 직접 부르고, 그날 화이트리스트가 없는 것과 같아진다.
그리고 **아무 오류도 안 난다** — 패치는 잘 적용되고, 그게 `src/test/` 였다는 것만 아무도 모른다.

⬜ **남은 구멍**: 「다른 코드가 `java.nio` 를 직접 부르면 빌드 실패」라는 검사는 **아직 없다.**
지금 실제로 막는 것은 **「적용 전에 경로를 확인한다」와 「테스트를 매번 새로 만든다」** 두 줄이다.

## 5. 무엇을 확인했나 — «가짜 LLM» 을 갈아 끼워서

규율 문서가 이 검사를 콕 집어 요구했다 —
*"화이트리스트가 `src/test/**` 패치를 실제로 거부하는지 (LLM을 가짜로 갈아끼우고)"*.

통과시키려고 무엇이든 하는 LLM 을 흉내 내어 여섯 가지 패치를 만들었다.

| 가짜 LLM 이 낸 것 | 결과 |
| --- | --- |
| 정직하게 고침 | ✅ **써진다** — 막기만 하는 장치는 쓸모가 없다 |
| 테스트를 지움 | 🔴 거절 + **파일이 안 생긴다** |
| 🔴 진짜 고침에 테스트 삭제를 «끼워 넣음» | 🔴 거절 + **진짜 고침도 안 쓴다** |
| 경로를 거슬러 올라가 CI 를 고침 | 🔴 거절 |
| 기록을 고침 | 🔴 거절 |
| 채점기 자신을 약화시킴 | 🔴 거절 |

🔴 **세 번째가 가장 중요하다.** 「멀쩡한 것만 골라 쓰기」를 하면 반쪽짜리 패치가 들어가고,
그건 LLM 이 의도한 것과 **다른 코드**가 된다. 하나라도 걸리면 **전부** 안 쓴다.

그리고 「거절했다」고 **말만** 하고 쓰면 아무 의미가 없으므로,
검사는 전부 **파일이 실제로 안 생겼는지**까지 본다.

✅ **일부러 깨뜨려 확인했다** — 금지 목록을 비우니 **27건 중 9건이 실패**했고,
되돌리니 통과했다.

## 6. ⬜ 무엇이 아직 확인 안 됐나

- 🔴 **이 통로를 «우회»할 수 있는지는 검사가 없다.** `java.nio` 를 직접 부르는 코드를
  빌드가 막지 않는다. 지금은 사람이 지킨다 — 즉 언젠가 안 지켜질 수 있다
- **심볼릭 링크 검사를 윈도우에서 못 돌렸다.** 권한 문제로 건너뛰어진다.
  리눅스 CI 가 생기면 그때 진짜로 확인된다
- **패치를 «되돌리는» 길이 없다.** 채점 네 겹 중 ㉣(패치를 되돌리면 다시 실패하나)을
  하려면 필요한데, 아직 없다
- **`git apply` 를 쓰지 않는다.** 지금은 「경로 → 새 내용」을 통째로 받아 쓴다.
  진짜 diff 를 다루게 되면 **diff 안에 든 경로도 같은 검사를 거쳐야** 하고,
  ⬜ 그게 이 구조로 충분한지는 **안 봤다**
- **증상 덮기 패턴**(새 `@ExceptionHandler` · 넓은 `catch` · 재시도 · 타임아웃 늘리기)을
  자동으로 「중간 확신도」로 내리는 것은 **아직 없다.** 설계에는 있다
