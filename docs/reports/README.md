# docs/reports — 그날그날 무슨 일이 있었나

**날짜 폴더 하나가 하루다.** 그 안에 주제별로 파일을 둔다.

```
docs/reports/
├── README.md                ← 이 파일. 색인
└── <YYYY-MM-DD>/
    ├── <주제>.md            그날 한 일 · 잰 것 · 나온 숫자
    └── troubleshooting/
        └── <증상>.md        막혔다가 푼 것
```

## 무엇을 어디에 적나

| 종류 | 자리 | 예 |
| --- | --- | --- |
| 「지금 무엇인가」 | `docs/PRD.md`·`DESIGN.md`·`DATA_CONTRACT.md`·`00_CODE_WALKTHROUGH.md` | 모듈이 몇 개인가 |
| 「왜 이렇게 정했나」 | `docs/rules/` — **주제별. 날짜 아님** | 왜 자바 21인가 |
| **「그날 무슨 일이 있었나」** | **여기 `<날짜>/`** | 실측 결과, 리뷰 |
| **「막혔다가 풀었다」** | **`<날짜>/troubleshooting/`** | 빌드가 왜 죽었나 |

🔴 **같은 내용을 두 곳에 적지 않는다.** 한쪽이 반드시 먼저 낡는다.
실측으로 설계가 바뀌면 **설계 문서를 고치고, 여기엔 「무엇을 재서 왜 바꿨나」만** 남긴다.

## 🔴 트러블슈팅 파일 이름은 «증상»으로 짓는다

다음에 찾을 때는 **증상으로 찾지 원인으로 찾지 않는다.** 원인을 알면 이미 해결한 것이다.

```
⭕ 테스트-출력의-한글이-깨진다.md
⭕ 빌드가-IBM_SEMERU-만-남기고-죽는다.md
❌ 인코딩-설정.md              ← 뭘 찾는지 모르면 못 찾는다
❌ foojay-플러그인-버전.md      ← 원인을 알아야 찾을 수 있다
```

**내용에 넣을 것**: 증상(실제 출력 그대로) → 원인 → 해결 → 🔴 **시도했다가 실패한 방법**.
마지막 것이 가장 값이 크다 — 다음 사람이 같은 막다른 길을 다시 걷지 않는다.
