# 만드는 순서 결정 — 바이트코드를 v0이 아니라 v1에 둔다

> **2026-09-10 결정.** 처음 계획은 에이전트부터 만드는 것이었다. 설계 리뷰가 이걸 뒤집으라고 했고,
> 받아들였다. 🔄 **이 프로젝트에서 가장 중요한 결정이다.**

## §1 무엇을 정했나

> **v0에서 바이트코드를 안 쓴다.** 기록은 `jakarta.servlet.Filter` 하나와 `DataSource` 를 감싸는
> 클래스 하나로 한다. `-javaagent`·ByteBuddy·셰이딩·클래스로더는 **전부 v1로 미룬다.**

v0의 목표는 **고리 전체가 한 바퀴 도는 것**이다 — 기록 → 재생 → 오라클 → 진단 → 채점 → PR.

## §2 무엇을 알고 그렇게 정했나

### 처음 순서의 문제

처음 계획은 v0=에이전트, v1=재생, v2=고리였다. 그런데 설계 문서 스스로가 **「③↔④ 되돌아가는
화살표가 이 프로젝트의 존재 이유」** 라고 적어 놓고, 그 존재 이유를 v2에 뒀다.

> 🔴 **일정이 밀리면 잘려나가는 건 항상 뒤쪽이다.**
> 즉 **잘릴 가능성이 가장 큰 것이 하필 핵심**이었다.

### 일정이 낙관적이었다

리뷰 판정: **v0 2~3주는 실제로 5~7주다.** 범인은 JDBC 계측이다.

- 인터페이스 셋(`Statement`·`PreparedStatement`·`ResultSet`)에 걸친 90개 남짓의 메서드
- 파라미터 곁표 — `setXxx` 40여 개를 모아 뒀다가 `execute` 때 묶는다. 풀에 든
  `PreparedStatement` 는 영원히 살아서 **누수 위험**도 있다
- 커넥션 풀 프록시와 드라이버 구현체가 **둘 다 잡혀 질의가 두 번 기록된다.**
  성공 기준이 「SQL 201건」인데 402건이 나온다
- `ResultSet` 접근자 계측은 **시스템에서 가장 뜨거운 경로**이자 메모리를 가장 많이 먹는 자리

⚠️ 그리고 이 프로젝트를 쓰는 사람의 다른 프로젝트는 전부 타입스크립트다.
`ClassFileTransformer` 를 짜 본 적도, 클래스로더 가시성 문제로 밤을 새운 적도 없다.
**해 본 사람 기준 1주, 처음이면 2~3주**로 봐야 한다.

### 뒤집으면 뭐가 좋아지나

```
처음 순서:  [ 위험한 것 5~7주 ] → [ 재현 ] → [ 고리 ]  → 데모는 10주 뒤
바꾼 순서:  [ 고리 전체 3~4주 ] → [ 위험한 것 ]        → 데모는 3주 뒤
                    ↑
             여기서 데모 영상이 나온다
```

- **위험보다 데모가 먼저 온다.** 면접을 만드는 건 3분짜리 영상이지 모듈 개수가 아니다
- **v1이 길어져도 멈출 수 있다.** v0이 이미 완결된 물건이니까
- **v1에 회귀 검사가 공짜로 생긴다** — 같은 상황에서 v0 기록기와 v1 에이전트가 같은 기록을
  만드는지 비교하면 된다. 「진짜 에이전트가 제대로 도는가」를 확인할 방법이 그냥 생긴다

## §3 무엇을 버렸나

| 안 쓴 길 | 왜 |
| --- | --- |
| 원래대로 에이전트부터 | 위 전부 |
| v0에서도 에이전트, 대신 범위를 줄여서 (결과 행·본문 빼기) | 리뷰가 제안한 대안이고 합리적이다. 하지만 **여전히 클래스로더·셰이딩·`premain` 을 다 해야 한다.** 위험의 대부분이 그대로 남는다 |
| 에이전트를 아예 안 만들고 라이브러리로 끝내기 | 「옵션 한 줄로 아무 앱에 붙는다」가 이 도구의 값어치다. **포기하는 게 아니라 미루는 것이다** |

## §4 🔴 값으로 치르는 것

**기록기를 두 번 만든다.** `hindsight-recorder-simple` 은 v1에서 에이전트로 대체된다.
버리는 값은 **나흘쯤**이다.

⚠️ 다만 **완전히 버리지는 않는다** — v1의 회귀 검사 대상으로 남는다.
🔴 두 기록기가 **같은 기록 형식**을 쓰게 만드는 것이 이 계획의 전제다.
형식이 갈라지면 회귀 검사가 성립하지 않고, 나흘이 아니라 2주를 버린다.
그래서 왕복 테스트(설계 §11)가 v0의 필수 과제다.

## §5 무엇이 이 결정을 뒤집게 만드나

- v0의 `Filter` + `DataSource` 방식으로 **오라클(§6-1)을 제대로 시험할 수 없다면** — 즉
  이 방식으로 만든 기록으로는 재생이 성립하지 않는다면 — 순서를 다시 본다.
  ⬜ **아직 확인 안 됨.** v0 첫 주에 가장 먼저 확인할 것
- v1이 6주를 넘기면 **거기서 멈추고 v0을 완성품으로 낸다.** 그게 이 순서를 택한 이유다
