# 재생 전 상태 복원 — 「쓰기 요청은 채점 못 한다」를 뒤집은 결정

> **2026-09-11 결정.** 하루 전 같은 날 오전에 내린 결론을 오후에 실측으로 뒤집었다.
> 🧭 근거가 된 숫자: [`reports/2026-09-11/write-replay-experiment.md`](../reports/2026-09-11/write-replay-experiment.md)

## 1. 무엇을 정했나

🔴 **재생은 「요청을 다시 보내는 것」이 아니라 「기록 시점 상태로 되돌린 뒤 요청을 다시 보내는 것」이다.**
복원은 재생의 준비 단계가 아니라 **재생의 정의 안에** 있다.

그리고 복원은 **어디까지 했는지 기록에 적는다.** 못 하면 등급이 `PARTIAL` 이고 `missing` 에
`"STATE"` 가 들어간다 — 조용히 통과시키지도, 「안 고쳐졌다」로 판정하지도 않는다.

## 2. 무엇을 알고 그렇게 정했나

### 뒤집기 전에는 이렇게 적혀 있었다

> 쓰기 요청은 재생해도 같은 답이 안 나온다. 네 등급 어디에도 안 맞으니
> 등급을 하나 더 만들거나, `id` 처럼 매번 달라지는 자리를 빼고 비교해야 한다.

### 왜 틀렸나

그 관찰은 **원인 후보 둘을 한 번에 바꾼 실험**에서 나왔다. 「쓰기 요청이라서」와
「DB 를 안 되돌려서」가 갈리지 않았다. 되돌린 범위만 바꿔서 세 번 재 보니 답이 나왔다.

| 되돌린 범위 | 재생 결과 |
| --- | --- |
| 없음 | 응답이 다르다 |
| 행만 | 🔴 재생이 예외로 죽는다 |
| 행 + 자동 증가 카운터 | ✅ 글자까지 같다 |

**축이 HTTP 메서드가 아니라 「복원했나」였다.** 되돌리지 않으면 읽기 요청도 갈라진다.

### 🔴 반대 근거 — 이걸 알고도 이렇게 정했다

- **운영 DB 는 이렇게 못 되돌린다.** 실험은 H2 메모리라 한 줄로 됐다. 진짜 서비스의 DB 를
  기록 시점으로 되돌리는 방법은 **아직 안 정했다.** 그래서 이 결정은 「복원을 한다」가 아니라
  **「복원 여부를 기록하고, 못 하면 그렇다고 말한다」**까지만 정한 것이다
- **복원 범위를 전수로 세지 않았다.** 지금 아는 「행으로 안 보이는 상태」는 자동 증가 카운터
  하나뿐이다. 캐시·정적 변수·외부 시스템은 설계 §4-2 가 애초에 「재현 안 된다」고 적어 둔 것이고,
  이 결정이 그걸 해결하지 않는다
- **복원을 잘못하면 더 나빠진다.** ⑦-B 가 그 모양이다. 행은 맞는데 `id` 가 어긋나서
  재생이 죽고, 채점기는 그걸 「패치가 못 고쳤다」로 읽는다. **부분 복원은 무복원보다 위험하다**

## 3. 무엇을 버렸나

| 버린 길 | 왜 |
| --- | --- |
| **다섯 번째 등급을 만든다** | 만들 이유가 사라졌다. 원인이 쓰기가 아니라 미복원이었으므로 네 등급으로 충분하다 |
| 🔴 **`id` 처럼 달라지는 자리를 빼고 비교한다** | **이 프로젝트가 금지한 모양이다.** 「다를 수 있으니 안 본다」는 「모름」을 「없음」으로 접는 것이다. 게다가 한 번 빼기 시작하면 무엇을 뺐는지 아무도 안 세고, 결국 `catch { return null; }` 같은 얕은 패치가 통과한다 |
| 「예외가 사라졌나」만 본다 | 위와 같은 이유. 응답 본문을 안 보면 예외를 삼키는 패치가 가장 쉬운 통과 경로가 된다 ([`DATA_CONTRACT`](../DATA_CONTRACT.md) §5-1-1) |
| 쓰기 요청은 아예 안 잡는다 | 🔴 **사고는 쓰기에서 더 많이 난다.** 잡을 수 있는데 안 잡는 것은 도구를 반으로 줄이는 일이다 |

## 4. 무엇이 이걸 뒤집게 만드나

- **운영 규모 DB 에서 복원 비용이 감당이 안 될 때.** 재생 한 번에 스냅숏 복원이 몇 분 걸리면
  고리가 안 돈다. 그때는 「기록된 질의에만 답하는 가짜 DB」 쪽으로 간다 (설계 §6-2 가 이미
  그 장치를 들고 있다)
- **자동 증가 카운터 말고 되돌려야 할 것이 줄줄이 나올 때.** 복원 목록이 길어질수록
  「복원했다」는 말의 신뢰가 떨어진다. 목록이 다섯을 넘으면 복원 방식을 다시 본다
- **복원했는데도 갈리는 사례가 나올 때.** 그건 복원 범위 밖의 비결정성(시각·난수·순서)이고,
  이 결정이 아니라 계측 쪽 문제다
