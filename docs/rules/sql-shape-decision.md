# 질의 「모양」을 어디까지 접나

> 이 파일은 **왜 그렇게 정했나**를 적는다. 지금 규칙 자체는
> [`SqlShapes`](../../hindsight-model/src/main/java/io/hindsight/model/SqlShapes.java) 에 있다.

---

## §1 접는 이유

이 도구는 N+1 을 **「같은 모양의 질의가 몇 번 반복됐나」**로 잡는다.

```
where id = 7  와  where id = 8  은 «같은 코드가 낸 같은 질의»다
  → 다른 것으로 세면 N+1 이 「서로 다른 질의 200개」로 보여서 안 잡힌다
```

2026-09-11 실측에서 **「총 횟수」보다 「모양별 반복」이 훨씬 강한 신호**라는 것이 나왔다
(주문 20건 → 한 모양이 20번). 그래서 오라클이 이 값을 쓴다.

---

## §2 🔴 IN 절을 접는다 (2026-09-16)

### 그 전에는 안 접었고, 그게 N+1 을 통째로 놓치게 했다

하이버네이트는 `IN` 의 인자 **개수**만큼 물음표를 붙인다. 그래서 **같은 코드 한 줄**이
`in (?,?)` · `in (?,?,?)` … 를 만들고, 그게 **서로 다른 모양**으로 세였다.

진짜 앱에서 재 봤다 (실험 ⑰).

```
같은 코드 한 줄이 만든 «서로 다른 모양»: 5가지

실제로 같은 코드가 돈 횟수: 5번
🔴 오라클이 보는 「가장 많이 반복된 모양」: 1번
```

**반복 문턱이 2 이므로 이 모양의 N+1 은 통째로 안 잡혔다.**

### ⚠️ 접으면 잃는 것

인자 2개짜리와 200개짜리가 **같은 모양**이 된다. 「몇 개였나」는 성능에서 중요한 정보다.

🔴 그런데 그건 **모양이 아니라 질의문 자체**에 남는다 — `events` 의 `sql` 은 안 건드린다.
**모양은 「세는 데」 쓰고, 읽는 것은 원문이다.**

### 🔴 IN 이 아닌 괄호는 안 건드린다

```
❌ coalesce(a, b, c) → coalesce(?)     서로 다른 질의가 한 모양이 된다
⭕ coalesce(a, b, c) → 그대로
```

접기가 과하면 **다른 질의가 합쳐져서**, 이번엔 「반복이 아닌 것」이 반복으로 보인다.
정규식이 `in` 다음의 괄호만 보는 이유다.

## §3 🔴 그래서 판 번호가 1 → 2 로 올라갔다

`Summary.SqlShape.sqlHash` 는 **파일에 저장되는 값**이다. 규칙이 바뀌면
**1판 파일에 적힌 해시를 지금 코드는 절대 만들어 내지 못한다.**

판 번호를 안 올리면 그 사실이 아무 데도 안 남고,
「같은 해시인데 왜 안 맞지」가 영영 안 풀린다.

⚠️ **1판 파일은 여전히 읽힌다** — 낮은 판은 거절하지 않는다.
다만 그 파일의 질의 해시는 지금 규칙의 해시와 **비교하면 안 된다.**

---

## §4 🔴 기록기와 재생이 «같은» 코드를 쓴다

`SqlShapes` 는 `hindsight-model` 에 있다. 기록하는 쪽과 재생하는 쪽이
**같은 클래스를 부른다** — 두 벌로 만들면 한쪽만 고쳐지고, 그러면
**모든 재생이 「모양이 달라졌다」로 나오면서도 아무 오류가 안 난다.**

그 계약은 `ShapeAgreementTest` 가 지킨다.

⚠️ `hindsight-model` 은 **의존성이 0** 이어야 하므로, 여기서 SQL 파서를 쓸 수 없다.
정규식 세 줄이 그 제약 안에서 고른 답이다.

---

## §5 ⬜ 아직 안 접는 것

```
⬜ VALUES (…), (…), (…)   — 대량 insert 의 묶음 크기
⬜ 주석 (/* … */)          — 하이버네이트가 붙이는 힌트 주석
⬜ 별칭 번호 (o1_0, m1_0) — 같은 질의라도 별칭 번호가 달라질 수 있다
```

전부 **같은 모양의 함정**이다. 지금은 겪지 않았고, 겪으면 여기에 줄이 하나 늘어난다.
🔴 **겪기 전에 접지 않는다** — 과하게 접으면 다른 질의가 합쳐지고, 그게 더 나쁘다.
