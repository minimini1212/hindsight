# Hindsight

**자바 앱이 사고 나면 그 순간으로 되돌아가, 재현하고 원인을 짚고 스스로 채점한 뒤 PR을 올립니다.**
배포 버튼은 사람이 누릅니다.

> *Hindsight is 20/20* — 지나고 나면 다 명확하다는 말입니다.
> 이 도구는 실제로 **지나간 그 자리로 돌아가서** 보게 해줍니다.

⚠️ **지금은 설계 단계입니다. 코드는 아직 없습니다.** ([TODOS.md](TODOS.md))

## 무슨 문제를 푸나

운영 중 오류가 났을 때 개발자의 시간은 **고치는 데** 들지 않습니다. **무슨 일이 있었는지
알아내는 데** 듭니다. 가장 자주 나오는 말이 *"우리 쪽에선 재현이 안 되는데요"* 인 이유는 단순합니다.

> **그 순간의 입력값이 아무 데도 안 남아 있습니다.**

새벽 3시에 협력사 API가 이상한 응답을 한 번 보냈고, 그걸로 NPE가 났습니다. 로그에는 스택
트레이스만 있습니다. **그 응답을 다시 얻을 방법이 없습니다.**

## 어떻게 도나

```
[상시]  최근 몇 초~몇 십 초의 경계 값을 링 버퍼에 들고 있다
          │ 예외 · 지연
① 포획   그 창을 파일 하나로 떨군다
② 재현   다시 흘려 넣어 실패하는 JUnit 테스트를 만든다
③ 진단   LLM이 원인과 패치를 낸다
④ 채점   ㉠ 패치 전에 실패했나 ㉡ 후에 통과하나 ㉢ 기존 테스트 다 통과하나 ㉣ 되돌리면 다시 실패하나
⑤ 제출   근거를 붙인 PR. 사람이 머지한다
```

### 🔴 채점기가 증명하는 것과 증명하지 않는 것

> **명백히 틀린 패치를 걸러냅니다. 맞는 패치임을 증명하지는 않습니다.**

「테스트가 통과했으니 고쳐진 것」은 자동 프로그램 수정 분야에서 이미 실패로 판명된 생각입니다
(측정된 과적합률 73~98%). 그래서 채점을 **증명이 아니라 거름망**으로 다루고, 네 겹으로 쌓고,
마지막에 반드시 사람을 세웁니다.

## 못 하는 것

| 못 하는 것 | |
| --- | --- |
| **앱 안에 쌓인 상태가 원인인 버그** | 캐시·세션·커넥션 풀. 요청 하나를 재생해도 이전 요청들이 쌓은 상태는 재현 안 됩니다 |
| 경쟁 상태의 완전 재현 | 연구 영역입니다. 「의심된다」까지만 말합니다 |
| **운영 배포** | 재생 통과는 「이 상황이 고쳐졌다」일 뿐 「다른 게 안 망가졌다」가 아닙니다 |
| 여러 서비스를 가로지르는 재현 | 범위 밖입니다 |

## 비슷한 것들

Keploy · ReCrash(2008) · 테스트 카빙 · JFR · APM · Sentry Autofix. **각각이 우리보다 나은 점을
[PRD.md §7](docs/PRD.md) 에 먼저 적어 뒀습니다.** 새로운 것은 **재생으로 LLM 패치를 걸러내는
고리** 하나이고, 나머지는 조합입니다.

## 구성

🔴 **모듈은 「누구의 클래스패스에 올라가나」로만 나눕니다.** 읽기·재생·진단·명령줄 같은
구분은 전부 패키지입니다. 그래서 전체 계획이 **6개뿐**입니다.

```
관측 대상 앱 «안»에서 도는 것  — 의존성을 함부로 못 늘린다
  ✅ hindsight-model      안팎이 공유하는 자료 구조 (Java 17 · 의존성 0)
  ⬜ hindsight-agent-boot 부트스트랩 껍데기 (Java 17)              [v1] ✅꼭 필요
  ⬜ hindsight-agent      premain · ByteBuddy(셰이딩) · 링 버퍼    [v1] ✅꼭 필요
  ⬜ v0 기록기            Filter + DataSource 감싸기        ⬜ 모듈일지 미정

바깥에서 도는 것
  ✅ hindsight-core       읽기 · 재생 · 오라클 · 진단 · 채점 · 명령어
                            └ 안은 패키지로: store · privacy · replay
                                            · guard · brain · cli · mcp
  ⬜ demo-app             관측 대상. 🔴 진짜 스프링 서비스로 만듭니다   ← 다음
```

🔴 **꼭 나눠야 하는 것은 `agent`·`agent-boot` 둘뿐이고, 둘 다 v1 입니다.**
`model` 은 v1 을 위한 규율이고(합쳐 두면 v1 에 레코드 여덟 개를 손봐야 합니다),
v0 기록기는 **아직 안 정했습니다** — 코드가 없는데 미리 정하지 않습니다.
⚠️ **지금 디스크에 실제로 있는 모듈은 2개입니다.**

⚠️ **폴더는 첫 파일을 쓸 때 만듭니다.** 빈 폴더는 「누가 시작해 놨나」로 읽혀서 다음 사람이
매번 열어 봐야 합니다. 지도는 디스크가 아니라
[00_CODE_WALKTHROUGH.md §2](docs/00_CODE_WALKTHROUGH.md) 에 있습니다.

## 시작하기

```bash
cp .env.example .env        # 값을 채운다
./gradlew build
```

⚠️ `gradle/libs.versions.toml` 의 버전은 **설계 시점의 값이고 아직 받아본 적이 없습니다.**
첫 빌드 때 확인하고 고쳐야 합니다.
